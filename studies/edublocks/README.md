# EduBlocks — 제품별 화면·기능·UX·기술 분석

> 조사 기준일: 2026-11-08  
> 확인 수준: 공식 기능 설명 기반; 현행 핵심 editor 저장소 구조 미확인  
> 근거: https://docs.edublocks.org/

## 1. 실제 파일·폴더 구조의 공개 여부

**현재 확인된 핵심 소스 폴더 없음.** 이 서비스의 내부 폴더 이름·상태 라이브러리·백엔드 API·DB 테이블을 추정해 적지 않습니다. 대신 공개 기능/화면과 기술적으로 필요한 개념 흐름을 분리합니다.

## 2. 제품 내 페이지·화면 인벤토리

1. 홈/프로젝트 생성
2. Python3·HTML·micro:bit 등 프로젝트 유형 선택
3. 블록 작업 공간
4. 생성된 텍스트 코드 비교
5. Classroom/교사 기능

이 목록은 기능상 구분되는 화면/모드를 정리한 것입니다. **URL, 실제 메뉴 계층, 모바일 레이아웃, 버튼 위치**는 브라우저별 상호작용 재현이 필요합니다.

## 3. 버튼·기능·상태 연결표

| 사용자 행동 | 확인된 역할·적용 조건 | 검증해야 할 예외 |
|---|---|---|
| 프로젝트 생성/유형 선택 | 언어·실행 환경별 블록 팔레트 초기화 | 저장·취소·상태 동기화/지원 환경 확인 |
| 블록 끌어오기 | 블록의 문법 대응 텍스트를 생성·갱신 | 저장·취소·상태 동기화/지원 환경 확인 |
| 텍스트 편집 | 텍스트 변경 후 native blocks 역변환은 별도 확인되지 않음 | 저장·취소·상태 동기화/지원 환경 확인 |
| 실행·저장 | 프로젝트 유형별 동작 조건 및 저장 포맷 미검증 | 저장·취소·상태 동기화/지원 환경 확인 |

## 4. 기술과 정보 흐름

공개 정보상 블록→코드 생성기 중심. parser/AST 내부 구조, 번들 구성, canonical 상태는 확인 불가.

## 5. 복잡하게 얽힌 문제의 풀어낸 방식

| 문제 | 사용한 접근 또는 분석상 확인 사항 |
|---|---|
| 한 블록과 한 코드 줄 연결 | 단순한 1블록≈1문장 원칙 |
| 두 표현을 동시에 표시 | 학습자의 문법 대응 이해 보조 |
| text edit 뒤 불일치 | 역변환 확인 전까지 단방향 편집으로 판정 |

## 6. UI/UX 심층 관찰 항목

- **첫 화면:** 진입부터 첫 코딩까지 단계·기본값·설명량
- **코딩 화면:** toolbox 탐색, 스크롤, 확대/축소, 작업공간 크기, 오류 시 시각 변화
- **표현 전환:** 토글/병렬/단계/하이브리드 중 어떤 흐름인가
- **기능별 버튼:** enabled/disabled/loading/error/confirm 상태와 접근성 label
- **연속성:** 이동 전후 코드·주석·저장 파일·블록 배치·기기 연결 보존
- **모바일/태블릿:** 화면 분할과 터치 드래그·가상 키보드 충돌
- **교육적 보조:** 초급 안내, 예시, 오류 설명, 학생이 원리를 발견하는 방식

**현재는 기능·공식 설명 분석 단계이며 실제 사용성 실험 결과는 아닙니다.**

## 7. 핵심 재사용 포인트

한 화면에 짧은 문법 대응을 드러내는 UX를 참고할 만하다.

## 8. 다음 검증 프로토콜

1. 실제 사이트에 접속해 각 화면의 정확한 URL·메뉴 동선 채집
2. 주요 버튼의 click→state→visible feedback→save 결과 기록
3. 블록 수정 후 코드와 코드 수정 후 블록 각각 시험
4. 불완전한 소스, 미지원 문법, Undo, 공유/내보내기 충돌 시험
5. 실제로 확인한 경우에만 버튼 문구·색상·위치·모달 내용을 확정
6. 내부 소스가 공개되면 해당 소스의 tree SHA와 핵심 경로 기록

## 9. 오해 방지

공개 문서에서 "블록과 Python을 모두 지원"하거나 "코드 생성"한다고 해서 **동일 프로젝트를 양방향으로 되돌릴 수 있다는 뜻은 아닙니다.** 검증되지 않은 내용은 미확인으로 유지합니다.
