# VEXcode Switch — 제품별 화면·기능·UX·기술 분석

> 조사 기준일: 2026-11-08  
> 확인 수준: 공식 지원 문서 기반; 핵심 편집기 소스 비공개  
> 근거: https://kb.vex.com/hc/en-us/articles/29201524290452-Using-Switch-Blocks-to-Transition-from-Blocks-to-Text-Based-Coding-in-VEXcode-V5

## 1. 실제 파일·폴더 구조의 공개 여부

**현재 확인된 핵심 소스 폴더 없음.** 이 서비스의 내부 폴더 이름·상태 라이브러리·백엔드 API·DB 테이블을 추정해 적지 않습니다. 대신 공개 기능/화면과 기술적으로 필요한 개념 흐름을 분리합니다.

## 2. 제품 내 페이지·화면 인벤토리

1. 프로젝트/기기 선택
2. 블록 기반 작업공간
3. Switch 블록이 포함된 하이브리드 화면
4. Python 코드 입력 부분
5. 로봇 실행/디버깅 환경

이 목록은 기능상 구분되는 화면/모드를 정리한 것입니다. **URL, 실제 메뉴 계층, 모바일 레이아웃, 버튼 위치**는 브라우저별 상호작용 재현이 필요합니다.

## 3. 버튼·기능·상태 연결표

| 사용자 행동 | 확인된 역할·적용 조건 | 검증해야 할 예외 |
|---|---|---|
| 블록 우클릭→Switch 전환 | 한 블록을 Python 명령 입력 블록으로 전환 | 저장·취소·상태 동기화/지원 환경 확인 |
| Switch 내부 코드 입력 | Python 텍스트를 시각 블록 트리 안에 배치 | 저장·취소·상태 동기화/지원 환경 확인 |
| 블록 유지/추가 | 시각적인 구조적 scaffold 유지 | 저장·취소·상태 동기화/지원 환경 확인 |
| 실행 | 정상 블록과 text island를 함께 처리하는 제품 동작 | 저장·취소·상태 동기화/지원 환경 확인 |
| 프로젝트 저장 | 혼합 표현이 유지되는지 실제 포맷 미검증 | 저장·취소·상태 동기화/지원 환경 확인 |

## 4. 기술과 정보 흐름

내부 AST 구조는 비공개. 'normal block + Python text payload'는 개념적 설계 모델이지 확인된 내부 파일 구조가 아님.

## 5. 복잡하게 얽힌 문제의 풀어낸 방식

| 문제 | 사용한 접근 또는 분석상 확인 사항 |
|---|---|
| 초보자의 완전 텍스트 전환 부담 | 한 블록씩 Python으로 전환 |
| 반복·조건 구조를 잃음 | 외곽 블록을 남긴 채 내부 명령만 text로 바꿈 |
| 텍스트→블록 전체 역변환 비용 | 범용 decompiler 대신 hybrid approach |

## 6. UI/UX 심층 관찰 항목

- **첫 화면:** 진입부터 첫 코딩까지 단계·기본값·설명량
- **코딩 화면:** toolbox 탐색, 스크롤, 확대/축소, 작업공간 크기, 오류 시 시각 변화
- **표현 전환:** 토글/병렬/단계/하이브리드 중 어떤 흐름인가
- **기능별 버튼:** enabled/disabled/loading/error/confirm 상태와 접근성 label
- **연속성:** 이동 전후 코드·주석·저장 파일·블록 배치·기기 연결 보존
- **모바일/태블릿:** 화면 분할과 터치 드래그·가상 키보드 충돌
- **교육적 보조:** 초급 안내, 예시, 오류 설명, 학생이 원리를 발견하는 방식

**현재는 기능·공식 설명 분석 단계이며 실제 사용성 실험 결과는 아닙니다.**

## 7. 핵심 재사용 포인트

완전 역변환이 아니라 학습 목적에 맞춰 문제 범위를 줄이는 훌륭한 사례.

## 8. 다음 검증 프로토콜

1. 실제 사이트에 접속해 각 화면의 정확한 URL·메뉴 동선 채집
2. 주요 버튼의 click→state→visible feedback→save 결과 기록
3. 블록 수정 후 코드와 코드 수정 후 블록 각각 시험
4. 불완전한 소스, 미지원 문법, Undo, 공유/내보내기 충돌 시험
5. 실제로 확인한 경우에만 버튼 문구·색상·위치·모달 내용을 확정
6. 내부 소스가 공개되면 해당 소스의 tree SHA와 핵심 경로 기록

## 9. 오해 방지

공개 문서에서 "블록과 Python을 모두 지원"하거나 "코드 생성"한다고 해서 **동일 프로젝트를 양방향으로 되돌릴 수 있다는 뜻은 아닙니다.** 검증되지 않은 내용은 미확인으로 유지합니다.
