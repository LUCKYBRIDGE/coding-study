# 분석 방법과 판정 기준

> 조사 기준일: 2026-11-08

이 저장소는 craft-anything식의 **Study → Model → Check → Capture** 흐름을 적용합니다. 목표는 기능 이름을 모으는 것이 아니라 실제 구현 원리와 한계를 재현 가능한 수준으로 이해하는 것입니다.

## 1. Study — 실제 제품과 근거 확인

우선순위는 다음과 같습니다.

1. 현재 공식 제품 페이지와 도움말
2. 공개 GitHub 저장소의 실제 코드
3. 공식 기술 문서
4. 학술 논문·연구 보고서
5. 제3자 튜토리얼은 공식 자료에서 확인되지 않는 UX를 보조할 때만 사용

마케팅 문구만으로 "양방향" 판정을 내리지 않습니다.

## 2. Model — 변환 흐름을 구조로 모델링

각 제품에서 아래 질문을 동일하게 답합니다.

### 표현
- 블록 내부 표현은 Blockly XML/JSON인가?
- 텍스트의 언어는 JavaScript, TypeScript, Python, C++ 중 무엇인가?
- 블록과 텍스트 중 무엇이 정본(source of truth)인가?
- 별도의 중간 표현(IR/AST)이 존재하는가?

### 블록 → 텍스트
- string generator인가?
- AST/IR printer인가?
- 생성 시 포맷과 주석을 보존하는가?
- 매번 전체 파일을 재생성하는가?

### 텍스트 → 블록
- parser가 있는가?
- compiler/decompiler가 있는가?
- 어떤 문법만 역변환되는가?
- 미지원 코드는 거부, raw/grey block 보존, 또는 손실 중 어느 방식인가?

### 동기화
- 토글 시점 변환인가?
- split view에서 실시간 동기화하는가?
- debounce가 있는가?
- 서로의 change event가 무한 루프를 만들지 않도록 어떤 guard를 두는가?

### 왕복 보존성
서로 다른 수준을 구분합니다.

- **S0 없음**: 블록→텍스트도 없음
- **S1 보기 전용**: 블록→텍스트만 표시
- **S2 편집 가능한 단방향**: 생성된 텍스트는 편집 가능하지만 텍스트→블록 없음
- **S3 제한적 왕복**: 지원 문법에 한해 양방향
- **S4 의미 왕복**: 표현이 달라져도 실행 의미가 안정적으로 보존
- **S5 구조 왕복**: 블록 구조, 주석, 배치, ID까지 높은 수준으로 복원

현실적인 교육용 도구 대부분은 S3~S4를 목표로 하며 S5는 매우 어렵습니다.

## 3. Check — "양방향" 판정 규칙

### 완전/실질 양방향
다음이 모두 확인되어야 합니다.

- 블록 편집 → 텍스트 변화
- 텍스트 편집 → 블록 변화
- 같은 프로젝트에서 왕복 가능
- 미지원 문법 또는 변환 실패 처리 방식이 존재

### 제한적 양방향
역변환은 되지만 언어 전체가 아니라 교육용 subset이나 API annotation이 있는 구문만 안정적으로 블록화되는 경우입니다.

### 단방향
블록에서 코드를 생성하거나 코드 뷰를 보여주지만, 자유롭게 수정한 텍스트를 원래 블록으로 되돌리지 못하는 경우입니다.

### 병렬 지원
블록 IDE와 텍스트 IDE를 모두 제공하지만 동일 프로그램 표현 간 변환 관계가 확인되지 않는 경우입니다.

### 하이브리드
VEX Switch처럼 블록 컨테이너 안에 텍스트 명령을 직접 넣어 "왕복" 문제를 일부 회피하는 방식입니다.

## 4. Capture — 각 문서에 반드시 기록할 항목

- 한 줄 판정
- 대상 사용자 / 교육 맥락
- 블록·텍스트 UX
- 실제 데이터 흐름
- parser / generator / decompiler 구조
- 실패·미지원 문법 처리
- 주석·포맷·블록 ID 보존
- 저장 포맷
- 성능과 동기화
- 교육적 장점
- 기술적 장점
- 기술 부채 / 위험
- 가져올 설계
- 그대로 복제하면 안 되는 부분
- 근거 링크
- 신뢰도

## 5. 신뢰도 표시

- **A — 직접 확인**: 공식 문서 + 공개 소스가 서로 일치
- **B — 공식 확인**: 공식 제품 문서에서 기능 확인, 핵심 구현 소스는 비공개
- **C — 연구/간접 확인**: 논문 또는 제3자 자료 중심
- **D — 미확인**: UI상 가능해 보이나 실제 왕복 동작을 검증하지 못함

## 6. 중요한 용어

### canonical representation
동일 프로그램의 여러 표현 중 시스템이 "진짜 상태"로 취급하는 표현.

### AST
텍스트 문법을 구조화한 추상 구문 트리. 텍스트→블록 역변환에서 가장 흔한 중간 계층.

### IR
여러 언어를 하나의 의미 구조로 통합하기 위한 중간 표현.

### decompiler
텍스트/컴파일러 AST에서 다시 블록이나 다른 고수준 표현을 생성하는 계층.

### raw / grey block
정식 블록으로 표현할 수 없는 코드를 문자열 형태로라도 보존하는 탈출구. 왕복 손실을 크게 줄입니다.
